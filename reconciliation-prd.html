二、核心概念与术语

对账单
某一维度（日期+渠道/日期+商户+厂商）下的对账结果汇总，是对账的基本单位
勾对
将两方数据逐笔匹配的过程。勾得上的叫「已勾对」，勾不上的叫「有差异」
已勾对
两方数据完全匹配（订单/金额一致
有差异
两方数据存在不一致，包括金额差异和单边账
金额差异
两边都有记录，但金额对不上
单边账
一方有记录，另一方没有。分为「平台单边」和「渠道/商户单边」
在途
平台侧已发生，但渠道账单尚未生成，次日账单到达后继续勾对
即充即退
充电模式：先充值一笔 + 退款一笔，1 笔业务订单 = 2 条资金流水
溯源
查看原始报文与交易链路，用于排查差异原因
重新对账
对失败的对账单再次执行勾对逻辑，通常在补单或修正后使用

1发起对账

运营人员在平台对账列表页点击「发起对账」，选择交易日期和渠道，系统自动执行对账任务。

  • 对账范围：按「日期 + 渠道」维度
  • 当前渠道：微信（可扩展支付宝、银联等）
  • 业务模式：即充即退（1 笔订单 = 充值 + 退款 2 条流水）

3对账报告（详情）

点击「查看详情」进入对账报告页，展示该日对账的资金流水级明细。

模块内容
筛选区交易渠道、订单号搜索、只看异常对账开关
4 个 KPI平台流水笔数、渠道流水笔数、已勾对资金金额、差异金额

设计要点：平台对账以「资金流水」为最小粒度，每一条流水独立判断勾对状态。即充即退模式下，充值和退款分开勾对，互不影响。在途状态的流水不参与差异金额计算，次日续对。

五、对账状态与差异类型体系

两级状态模型

对账状态分为汇总级和明细级两层，层层递进，自上而下钻取。

层级状态含义出现位置
对账成功该对账单下所有明细全部已勾对，无差异对账列表
汇总级对账失败该对账单下存在至少一笔有差异对账列表
明细级已勾对两方数据完全匹配对账报告明细
明细级有差异存在金额差异或单边账对账报告明细
明细级在途渠道账单未到，次日续对（仅平台对账有）对账报告明细

有差异的三种情况拆解

「有差异」不是一个单一状态，它包含三类具体差异类型，在「对账结果/差异说明」列中展示。

对方无对应记录] D --> D1[对方有记录

差异类型平台对账商户对账说明常见原因
金额差异✓✓两边都有，但金额对不上手续费、优惠计算口径不同、汇率、 rounding
平台单边✓✓平台有，对方没有对方漏单、未同步、测试订单
渠道/商户单边✓（渠道单边）✓（商户单边）对方有，平台没有平台漏单、丢单、数据同步延迟
在途✓✗平台有，渠道账单次日才到T+1 账单机制
为什么平台对账独有「在途」状态的设计逻辑：渠道（尤其退款通常是 T+1 出账单，当日发生的退款可能要次日才出现在渠道账单中。因此平台对账引入「在途」状态，当天不记为差异，次日账单到达后自动续对，避免虚惊一场，也让差异数据更干净。

八、对账闭环：从发起到处理

flowchart LR A[1.发起对账] --> B[2.自动勾对] B --> C[3.生成对账单] C -->|对账成功| D[4.正常结算] C -->|对账失败| E[5.运营排查差异] E --> F{6.差异原因} F -->|金额差异| G[调账/退款修正] F -->|单边账| H[补单/确认] F -->|在途| I[等待次日续对] G --> J[7.重新对账] H --> J J --> B style A fill:#2563eb,color:#fff style D fill:#16a34a,color:#fff style E fill:#dc2626,color:#fff style I fill:#d97706,color:#fff
  1. 发起对账：运营按日期/商户发起，系统自动执行
  2. 自动勾对：系统按规则逐笔匹配，生成勾对结果
  3. 生成对账单：按维度汇总，标记对账成功/失败
  4. 正常结算：对账成功的对账单可直接用于财务结算
  5. 运营排查：对账失败的，运营进入详情页查看差异明细
  6. 差异原因：通过「对账结果/差异说明」和「溯源」定位原因
  7. 重新对账：问题修正后，重新执行勾对，直至对账成功

在途状态的流水不需要人工介入，系统次日自动续对，形成自动化闭环。

闭环的关键设计：每一笔差异都有明确的「状态」+「结果类型」+「原因说明」，让运营人员看到差异时，立刻知道「是什么问题」+「为什么会这样」+「大概怎么处理」，而不是只看到一个红色的「有差异」。这大大降低沟通成本，也让对账结果更可信。

九、关键指标（KPI 口径说明

平台对账 KPI

KPI计算公式说明
平台流水笔数充值流水数 + 退款流水数平台侧全部资金流水总量
渠道流水笔数已勾对且有渠道金额的流水数渠道账单中匹配到的数量
已勾对资金金额已勾对充值 − 已勾对退款（净额）实际已勾对的资金净额
差异金额金额差异 + 单边金额合计含金额差异笔数、单边笔数、在途笔数

商户对账 KPI

KPI计算公式说明
平台订单数平台侧订单总数含已勾对 + 有差异
商户订单数商户侧订单总数含已勾对 + 有差异
已勾对资金金额已勾对订单的金额合计对平的总金额
差异总金额所有差异订单的差异金额合计含金额差异笔数、单边笔数
